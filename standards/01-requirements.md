# 01 · 需求 / 活 PRD 〔本项目活记忆 · AI 维护〕

> **作用**:这是本项目唯一的需求文档。所有新功能、缺陷、技术债都追加到这里,不要另起多个 PRD 文件。
> **更新时机**:每次有新需求、需求变更、验收标准变化时更新。

---

## 1. 需求来源

| 类型 | 来源 | 进入方式 |
|---|---|---|
| 功能需求 Feature | 用户 / 老师 / 产品 / 客户 | 写成用户故事 |
| 缺陷 Bug | 测试 / 线上日志 / 用户反馈 | 写复现步骤和期望结果 |
| 技术债 Tech Debt | 开发 / Review / CI/CD 故障 | 写影响和修复目标 |

---

## 2. Issue 生命周期

| 阶段 | 状态 | 动作 |
|---|---|---|
| 提出 | Open | 写清场景、目标、验收标准 |
| 排期 | Backlog / Todo | 决定优先级和负责人 |
| 开发 | In Progress | 从 main 开 feature 分支 |
| 评审 | In Review | 提 PR,等待 CI 和 Review |
| 合并 | Done | PR 合并 main,自动关闭 Issue |
| 验收 | Verified | 按验收标准确认 |

**追踪规则**:分支名带 Issue 号,PR 描述写 `closes #<编号>`。

## 4. 需求清单

### US-1 初始化项目工程化与 CI/CD · 状态: Backlog

作为 **项目开发者**,
我想要 一个可运行、可测试、可部署的项目骨架,
以便 后续数据分析页面和在线预测功能都能在统一工程规范下稳定交付。

验收标准:
- AC1: Given 仓库初始化完成,When 查看项目结构,Then 至少包含 Streamlit 应用代码目录、测试目录、依赖文件、Dockerfile 与 GitHub Actions 工作流文件。
- AC2: Given 开发者在本地执行质量命令,When 运行 `ruff format --check .`、`ruff check .` 与 `pytest`,Then 命令可以执行且结果被纳入项目标准流程。
- AC3: Given 创建 Pull Request,When CI 运行,Then 至少包含格式检查、静态检查、单元测试、覆盖率检查与 Docker 构建检查。
- AC4: Given 代码合并到 `main`,When CD 运行,Then 系统会自动部署并验证 8004 端口上的服务可访问。
- AC5: Given 每次阶段性完成,When 会话结束前检查项目文档,Then `standards/PROGRESS.md` 已记录当前状态、下一步和关键决策。

技术备注:
- 以 Python 3.11、streamlit、pytest、ruff、Docker 为固定技术栈。
- 目标是完整跑通 CI + CD,不是只完成本地演示。

### US-2 交互式银行营销数据分析页面 · 状态: Backlog

作为 **业务分析者/课程演示者**,
我想要 一个可交互的数据分析页面,
以便 直观看到银行营销数据的结构、分布、特征关系和认购情况。

验收标准:
- AC1: Given 应用已启动,When 打开数据分析页面,Then 页面能够成功加载 `data/train.csv` 并展示数据概览,至少包含样本量、字段数和目标字段 `subscribe` 的说明。
- AC2: Given 用户进入分析页面,When 浏览页面内容,Then 至少可以看到数值特征分布、类别特征分布以及 `subscribe` 相关对比中的若干核心图表或统计结果。
- AC3: Given 用户需要交互探索,When 通过页面控件筛选字段、类别或样本范围,Then 页面会刷新相应分析结果而不需要修改代码。
- AC4: Given 页面展示分析结论,When 用户查看结果,Then 关键指标、图表标题和字段含义清晰,能够支持课堂讲解或业务解读。
- AC5: Given 数据文件缺失或读取失败,When 用户打开分析页面,Then 页面会给出可理解的错误提示,而不是直接崩溃。

技术备注:
- 优先使用 Streamlit 原生组件完成交互。
- 分析逻辑应与展示逻辑分离,便于测试和复用。

### US-3 离线训练认购预测模型 · 状态: Backlog

作为 **项目开发者/数据建模者**,
我想要 基于训练数据离线训练一个认购预测模型,
以便 为在线预测页面提供稳定、可复现的模型产物。

验收标准:
- AC1: Given 存在 `data/train.csv`,When 执行训练流程,Then 系统会完成数据预处理、模型训练与验证,并生成可供推理使用的模型产物。
- AC2: Given 训练流程完成,When 查看输出,Then 至少记录所使用的特征、预处理方式、模型类型以及 Accuracy、Precision、Recall、F1 等验证指标。
- AC3: Given 相同代码和相同输入数据,When 重新执行训练流程,Then 结果应可复现到合理范围内,且随机性已被控制。
- AC4: Given 训练产物生成后,When 项目运行在线预测功能,Then 应能成功加载该产物而不需要重新训练。
- AC5: Given 训练流程被纳入测试或校验范围,When 关键预处理或模型接口发生变更,Then 至少有测试覆盖主要数据处理和推理契约。

技术备注:
- 首版以离线训练为主,不要求在线增量学习。
- 模型文件默认不提交到 Git,应通过构建/部署流程或约定目录管理。

### US-4 在线认购预测页面 · 状态: Backlog

作为 **业务使用者**,
我想要 通过点选式表单输入客户特征并立即得到预测结果,
以便 快速判断该客户是否可能认购银行产品。

验收标准:
- AC1: Given 应用已启动且模型产物可用,When 打开预测页面,Then 页面展示与模型输入字段对应的点选式或表单式输入控件,不要求用户手写原始 CSV。
- AC2: Given 用户填写完必要字段,When 提交预测,Then 页面返回该客户是否会认购的预测结果。
- AC3: Given 模型支持概率输出,When 展示预测结果,Then 页面同时展示预测标签与相应置信度/概率;若暂不支持概率,则需在页面中明确说明。
- AC4: Given 用户输入缺失、非法或与训练特征不兼容,When 提交预测,Then 页面给出明确提示并阻止错误推理。
- AC5: Given 模型文件不存在或加载失败,When 用户进入预测页面,Then 页面应提示当前不可预测及原因,而不是出现未处理异常。

技术备注:
- 输入控件选项应与训练数据中的类别和取值范围保持一致。
- 预测页和分析页可以在同一个 Streamlit 应用中通过多页面或导航区分。

## 5. 非功能需求

- **安全**:密钥只进 Secrets,不进 Git。
- **可维护**:一需求一小 PR,避免大爆炸式提交。
- **可测试**:核心逻辑必须有单元测试,核心代码覆盖率目标 `>=80%`。
- **可部署**:部署后必须能在 `8004` 端口访问服务,并完成自动化部署验证。
- **可复现**:训练流程必须固定随机种子,保证结果可复核。
- **可演示**:页面应适合课堂展示,分析与预测路径都需能独立走通。
